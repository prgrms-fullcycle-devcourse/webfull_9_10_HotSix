Redis Key-Value Specification

현재 백엔드 구현에서 실제로 사용하는 Redis 키 구조를 정리한 문서입니다. 배틀 상태, 타이머 락, 로비 플레이어 집합을 중심으로 확인할 수 있습니다.

Storage: Redis Client: ioredis Primary Domain: battle / lobby Connection: REDIS_URL

키 요약

Key Prefix / Pattern Key 이름 Data Type Value 구조 / 설명 TTL (만료 시간) 비고
battle:current-game-id battle:current-game-id String 현재 활성 게임을 가리키는 gameId 문자열 없음 현재 게임 포인터
battle:game:{gameId}:state battle:game:{gameId}:state String(JSON) CurrentGameState 전체 JSON 문자열 없음 게임 상태 스냅샷
battle:timer-lock battle:timer-lock String 타이머 실행권을 의미하는 lockToken 문자열 1초 중복 타이머 실행 방지용 락
lobby:players lobby:players Set 로비에 입장한 플레이어 userId 집합 없음 현재는 퇴장 정리 로직 없음

운영 규칙

  • battle:current-game-id 와 battle:game:{gameId}:state 는 항상 같이 사용됩니다.
  • 대기 타이머는 battle:timer-lock 을 먼저 획득한 인스턴스만 실행합니다.
  • 게임 시작 조건은 Redis 상태의 playerCount >= minPlayers 입니다.
  • 대기 시간이 끝났는데 플레이어가 4명 미만이면 같은 gameId 상태에서 대기 시간만 15분 다시 시작합니다.
  • prompt.content 전체 문자열은 Redis 원본 상태에는 저장되지만, Socket 응답에서는 phase 와 stage 에 따라 노출 여부가 달라질 수 있습니다.
