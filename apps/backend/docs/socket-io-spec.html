Socket.IO Event Specification

현재 백엔드 구현 기준으로 프론트엔드가 바로 연동할 수 있도록 정리한 실시간 이벤트 문서입니다. 연결 직후 이벤트 순서, 대기 상태 타이머, 시작 조건, payload 구조를 기준으로 작성했습니다.

Protocol: Socket.IO Namespace: / Server: http://localhost:3000 Timer: 1 second broadcast

Payload 타입

PromptSnapshot

{
  id: number,
  slug: string,
  title: string,
  content: string,
  contentLength: number
}

PromptSummary

{
  id: number,
  title: string,
  contentLength: number
}

StatePayload

{
  gameId: string,
  prompt: PromptSnapshot,
  phase: "waiting" | "in_progress" | "finished",
  minPlayers: number,
  playerCount: number,
  spectatorCount: number,
  waitingEndsAt: string | null,
  gameStartedAt: string | null,
  gameEndedAt: string | null
}

WaitingPayload

{
  gameId: string,
  phase: "waiting",
  prompt: PromptSummary,
  remainingSeconds: number,
  waitingEndsAt: string,
  minPlayers: number,
  playerCount: number,
  spectatorCount: number
}

Lifecycle

  • 서버 시작 시 현재 게임 상태가 없으면 새 waiting 게임을 생성합니다.
  • 대기 상태에서는 1초마다 battle:waiting 이 모든 클라이언트에게 전송됩니다.
  • 남은 시간이 10초 이하가 되면 battle:countdown 이 한 번 전송됩니다.
  • 남은 시간이 0초가 되었을 때 playerCount >= minPlayers 이면 게임이 시작됩니다.
  • 남은 시간이 0초인데 플레이어가 4명 미만이면 게임을 시작하지 않고 대기 15분을 다시 시작합니다.
  • 게임 종료 후에는 새 waiting 게임이 즉시 생성되고 다시 대기 사이클로 돌아갑니다.

Frontend Notes

  • battle:state 에는 현재 구현 기준으로 prompt.content 전체가 포함됩니다.
  • battle:waiting 과 battle:countdown 에는 본문 전체가 아니라 title, contentLength 만 포함됩니다.
  • battle:player-ready 는 broadcast 이벤트라서 요청한 본인에게는 오지 않습니다.
  • 연결 직후에는 battle:welcome, battle:join 또는 battle:spectate, battle:state, 필요 시 battle:waiting 을 함께 처리해야 합니다.
